<h1>Пояснительная записка</h1>
<p>к предложению по реализации модуля &laquo;Обратная связь&raquo; в мобильном приложении</p>
<p>&nbsp;</p>
<p>В рамках предварительного анализа нами была проведена оценка реализации в мобильном приложении функционала &laquo;Обратная связь&raquo;. Данный модуль позволит пользователям формировать и отправлять обращения, а также отслеживать статус и результаты их рассмотрения (если есть личный кабинет). Для заказчика будет предусмотрена аналогичная функциональность с поддержкой на стороне административной панели. Ниже представлено наше видение архитектуры, логики работы и этапов внедрения функционала.</p>
<h2>1.&nbsp;&nbsp;&nbsp;&nbsp; Процесс взаимодействия пользователя с системой</h2>
<p>В мобильном приложении в основном меню предлагается добавить раздел &laquo;Обратная связь&raquo;. При переходе в раздел пользователь сможет:</p>
<ol>
<li>выбрать тему обращения;</li>
<li>указать текст вопроса или обращения;</li>
<li>при необходимости прикрепить файл или фотографию;</li>
<li>указать контактные данные, для получения ответа;</li>
<li>ознакомиться с информацией об обработке персональных данных;</li>
<li>отправить обращение.</li>
</ol>
<p><strong>Вариант 1.</strong> Без личного кабинета. Ответ приходит на указанный контакт (email/телефон), статус не отслеживается. После отправки пользователю отображается уведомление об успешном принятии обращения и присваивается уникальный номер обращения. При необходимости также может быть предусмотрено push-уведомление.</p>
<p><strong>Вариант 2. </strong>С личным кабинетом. Полный цикл с историей и перепиской. В разделе &laquo;Обратная связь&raquo; целесообразно предусмотреть подраздел &laquo;Мои обращения&raquo;, в котором пользователь сможет просматривать ранее направленные обращения и их текущий статус. Для обращений, по которым требуется дополнительная информация, реализовать возможность вести переписку с ответственным сотрудником непосредственно в рамках карточки обращения. Здесь требуется уточнение по интеграции с ЕСИА, регистрацией пользователя.</p>
<h2>2.&nbsp;&nbsp;&nbsp;&nbsp; Обработка обращений со стороны Заказчика</h2>
<p>Для работы с обращениями предлагается расширить существующую административную панель. Сотрудник получит доступ к единому реестру обращений, содержащему:</p>
<ol>
<li>номер обращения;</li>
<li>дату и время поступления;</li>
<li>тему обращения;</li>
<li>текст обращения;</li>
<li>приложенные материалы;</li>
<li>сведения о пользователе (контактные данные);</li>
</ol>
<p>И дополнительно, при необходимости:</p>
<ol start="7">
<li>текущий статус (с возможностью его изменить);</li>
<li>ответственного сотрудника;</li>
<li>историю изменения статусов;</li>
<li>ответ на обращение.</li>
</ol>
<p>После поступления обращения оно автоматически регистрируется в административной панели и получает уникальный идентификатор. Далее ответственное подразделение назначает его соответствующему сотруднику. Сотрудник рассматривает обращение и формирует ответ.</p>
<p>Для повышения эффективности работы рекомендуется предусмотреть поиск и фильтрацию обращений в административной панели, по статусу, теме, периоду, ответственному сотруднику и номеру обращения.</p>

<h2>4.&nbsp;&nbsp;&nbsp;&nbsp; Список специалистов для реализации</h2>
<p>Для успешной реализации проекта необходима следующая команда (внутренние ресурсы нашей компании):</p>
<ol>
<li>Системный аналитик &ndash; для детализации требований, составления технического задания, тестирования функционала.</li>
<li>UX/UI Дизайнер &ndash; для проектирования удобного интерфейса формы ввода и экрана истории переписки.</li>
<li>Разработчик backend &ndash; для создания API-методов обработки заявок и интеграции с базой данных.</li>
<li>Разработчик frontend &ndash; для внедрения UI-компонентов и настройки отправки уведомлений, доработка административной панели.</li>
<li>DevOps-инженер &ndash; для настройки серверной инфраструктуры, CI/CD, мониторинга и развертывания.</li>
<li>Руководитель проекта &ndash; для связи с заказчиком, передачи работ и контроля сроков.</li>
</ol>
<h2>5.&nbsp;&nbsp;&nbsp;&nbsp; Уточняющие вопросы</h2>
<ol>
<li>Реализован ли личный кабинет на сайте? Если да, необходим ли функционал просмотра отправленных обращений и их статуса в личном кабинете? Требуется ли вести переписку с пользователями?</li>
</ol>
<p>а) Реализован ЛК. Делаем функционал &laquo;Мои обращения&raquo; в ЛК и реализовываем переписку пользователя и ответственными лицами Заказчика.</p>
<p>б) Реализован ЛК. Функционал &laquo;Мои обращения&raquo; не нужен, возможность переписки также не нужна;</p>
<p>в) ЛК на сайте не реализован, но требуется его разработка в рамках проекта.</p>
<p>г) Реализации ЛК нет, требуется только функционал отправки обращений в административную панель.</p>
<ol start="2">
<li>Какие темы обращений требуется добавить?</li>
</ol>
<p>а) &laquo;Техническая проблема&raquo;, &laquo;Вопрос&raquo;, &laquo;Жалоба&raquo;, &laquo;Предложение&raquo;, &laquo;Благодарность&raquo;, &laquo;Другое&raquo;.</p>
<p>б) Свой вариант.</p>
<ol start="3">
<li>Требуется ли добавлять поле с возможностью прикреплять файлы?</li>
</ol>
<p>а) Требуется. Добавляем возможность прикреплять пользовательские файлы (.bmp, .jpeg,&nbsp;.gif,&nbsp;.tif,&nbsp;.tiff,&nbsp;.docx,&nbsp;.pptx,&nbsp;.rtf,&nbsp;.txt,&nbsp;.pdf,&nbsp;.xlsx,&nbsp;.csv,&nbsp;.ods,&nbsp;.odt.)</p>
<p>б) Не требуется, принимаем только текст.</p>
<p>в) Свой вариант.</p>
<ol start="4">
<li>Какие уведомления требуются: push-уведомления, уведомления внутри приложения, на электронную почту или их комбинация?</li>
</ol>
<p>а) Push-уведомления + уведомления внутри приложения.</p>
<p>б) Push + email.</p>
<p>в) Push + in-app + email (максимальный охват).</p>
<p>г) Только внутри приложения (без push).</p>
<p>д) Свой вариант.</p>
<ol start="5">
<li>Необходима ли интеграция с госуслугами ЕСИА?</li>
</ol>
<p>а) Требуется авторизация через ЕСИА (вход в ЛК через Госуслуги).</p>
<p>б) Не требуется, используется собственная авторизация.</p>
<p>в) Свой вариант.</p>
<ol start="6">
<li>Какие данные о пользователе должны передаваться сотрудникам Заказчика?</li>
</ol>
<p>а) ФИО/Название организации, email, телефон &ndash; минимальный набор.</p>
<p>б) Минимум + социальный статус (рабочий, студент и др.), льготный статус (ветераны, многодетные семьи и др.).</p>
